# Feature Specification: Markdown Dictation Export

**Feature Branch**: `codex/flowspeech-2`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "Сохранять все завершённые диктовки в Markdown-
файле за день в выбранной папке; Obsidian не является обязательным."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Save Every Dictation (Priority: P1)

Пользователь выбирает папку для экспорта и включает автосохранение. После
каждой завершённой диктовки он получает блок с итоговым текстом и временем в
дневном Markdown-файле. Отдельные файлы доступны как альтернативный режим.

**Why this priority**: Мысли остаются доступны даже если активное приложение
не приняло вставку, а выбранная папка может быть обычной папкой или vault.

**Independent Test**: В пустой выбранной папке пользователь завершает
диктовку и открывает ровно один созданный Markdown-файл с ожидаемым текстом.

**Acceptance Scenarios**:

1. **Given** автосохранение включено и выбрана доступная папка, **When**
   пользователь завершает распознанную диктовку, **Then** создаётся один
   дневной Markdown-файл получает один блок с итоговым текстом, временем
   создания и уникальным идентификатором диктовки.
2. **Given** вставка в активное приложение не удалась, **When** итоговый текст
   готов, **Then** Markdown-файл всё равно сохраняется, а пользователь видит
   независимые статусы вставки и сохранения.
3. **Given** выбранная папка является vault, **When** заметка сохранена,
   **Then** её можно открыть и прочитать как обычный Markdown-файл без
   изменения существующих настроек vault.

---

### User Story 2 - Control What Is Stored (Priority: P2)

Пользователь понимает, где появятся файлы, и может выключить экспорт, не
теряя уже созданные заметки.

**Why this priority**: Диктовки могут содержать личные сведения, поэтому
сохранение должно быть явным и предсказуемым.

**Independent Test**: Пользователь включает экспорт, видит пример пути,
выключает его и убеждается, что новая диктовка не создаёт файл, а старый
остался на месте.

**Acceptance Scenarios**:

1. **Given** пользователь выбирает папку, **When** он подтверждает настройку,
   **Then** интерфейс показывает будущий путь сохранения и проверяет, что в
   папку можно записать тестовую заметку.
2. **Given** экспорт выключен, **When** пользователь завершает диктовку,
   **Then** приложение не создаёт экспортную заметку.
3. **Given** экспорт был выключен, **When** пользователь открывает созданные
   ранее заметки, **Then** они остаются без изменений.

---

### User Story 3 - Recover From a Save Failure (Priority: P3)

Если выбранная папка недоступна, пользователь не теряет готовый текст и может
повторить сохранение после исправления проблемы.

**Why this priority**: Ошибка диска, прав или синхронизации не должна
превращать полезную диктовку в потерянную.

**Independent Test**: На недоступной папке приложение показывает ошибку и
действие «Повторить сохранение»; после выбора доступной папки та же диктовка
сохраняется один раз.

**Acceptance Scenarios**:

1. **Given** папка недоступна, **When** приложение пытается сохранить
   диктовку, **Then** оно не сообщает об успехе, сохраняет текст для повтора
   в рамках выбранной политики хранения и предлагает понятное действие.
2. **Given** сохранение уже удалось, **When** пользователь повторяет действие
   по ошибке, **Then** приложение не создаёт дубликат заметки.

### Edge Cases

- Папка удалена, стала доступной только для чтения или была перенесена между
  выбором и завершением диктовки.
- Две диктовки завершились с одинаковыми временем создания и первой строкой.
- Текст содержит кириллицу, символы Markdown, пустые строки, очень длинную
  фразу или имя, недопустимое для имени файла.
- Пользователь отменил диктовку или распознавание не вернуло текст.
- Внутренняя история отключена, но экспорт Markdown явно включён.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Пользователь MUST иметь возможность включить или выключить
  автосохранение Markdown-диктовок и выбрать единственную папку назначения.
- **FR-002**: При включённом экспорте система MUST по умолчанию добавлять
  одну завершённую диктовку в файл `YYYY-MM-DD.md` выбранной папки. Режим
  отдельных файлов MUST оставаться доступным.
- **FR-003**: Каждая экспортная заметка MUST содержать итоговый текст, время
  создания и устойчивый уникальный идентификатор диктовки.
- **FR-004**: Система MUST сохранять Markdown независимо от результата
  вставки текста в активное приложение.
- **FR-005**: Система MUST показывать отдельный итог для вставки и для
  экспорта, включая действие повтора для неудачного экспорта.
- **FR-006**: Повтор экспорта одной и той же диктовки MUST обновлять или
  подтверждать исходную заметку и MUST NOT создавать дубликат.
- **FR-007**: Система MUST проверять выбранную папку до включения экспорта и
  MUST сообщать, если проверка не удалась.
- **FR-008**: Система MUST NOT создавать экспорт для отменённой, пустой или
  нераспознанной диктовки.
- **FR-009**: Отключение экспорта MUST NOT удалять или изменять заметки,
  созданные ранее.
- **FR-010**: Экспорт MUST работать с любой локальной папкой. Он MAY работать
  с папкой внутри Obsidian vault, но не требует Obsidian и не читает другие
  Markdown-файлы.
- **FR-011**: Система MUST экспортировать Markdown только при явном включении
  экспорта. Настройка срока хранения внутренней истории сама по себе MUST NOT
  включать экспорт.
- **FR-012**: Система MUST сохранять Unicode-текст без потери кириллицы и
  создавать имена файлов, допустимые в выбранной файловой системе.

### Key Entities *(include if feature involves data)*

- **Export destination**: Выбранная пользователем папка, режим `daily` или
  `separate` и включённое состояние автосохранения.
- **Dictation export**: Связь одной завершённой диктовки с её Markdown-блоком
  или файлом, статусом сохранения и идентификатором повтора.
- **Export result**: Независимый итог сохранения: ожидает, сохранён, не
  сохранён или пропущен.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В 100 последовательных завершённых диктовках в доступную папку
  дневной файл содержит ровно 100 читаемых блоков с разными session ID.
- **SC-002**: В 100 повторных попытках сохранить уже экспортированную
  диктовку не появляется ни одного дополнительного файла.
- **SC-003**: В 20 проверках с неудачной вставкой готовый текст остаётся
  доступен и экспортируется, если назначение доступно.
- **SC-004**: Пользователь включает экспорт, завершает тестовую диктовку и
  открывает результат не более чем за 2 минуты без терминала или правки
  конфигурационного файла.
- **SC-005**: В 20 тестах кириллицы, смешанного языка и Markdown-символов
  текст заметок совпадает с итоговым текстом диктовки.

## Assumptions

- Основной продукт работает на macOS с локальной файловой системой.
- Пользователь выбирает папку через интерфейс и имеет права записи в неё.
- Экспорт Markdown хранит только итоговый текст по умолчанию. Исходный текст,
  данные приложения и аудио не экспортируются в этой части.
- Запись в уже открытую редактируемую заметку является отдельной следующей
  функцией и не входит в этот срез.
- Если пользователь явно включил Markdown-экспорт, он понимает, что внешняя
  синхронизация выбранной папки управляется сторонним сервисом, а не
  FlowSpeech.
