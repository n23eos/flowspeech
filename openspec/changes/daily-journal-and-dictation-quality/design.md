## Context

Дата: 2026-09-23. Основание: текущие исходники и запрос пользователя на план OpenSpec. Планирование, не реализация.

`markdown_export.py` добавляет блок с UUID и временем в YYYY-MM-DD.md; используется flock и fsync. Это защищает от сотрудничающих писателей, но не гарантирует защиту от внешнего редактора. `_failed_markdown_export` хранит только последнюю ошибку в памяти. В `main.py` дата и UUID создаются после распознавания, настройки читаются во время обработки, экспорт предшествует вставке. `hotkey.py` вызывает callbacks в потоке listener; `main.py` различает короткое нажатие и удержание через time.time(). Микрофон открывается только на время записи, хвост захвата составляет 250 мс. Предыдущие результаты тестов не являются новым baseline скорости или качества.

## Goals / Non-Goals

**Goals:** отдельная быстрая запись в дневник, сохранность подтверждённых записей, удобное чтение и правка, измеримые задержки и качество обоих движков.

**Non-Goals:** фоновое постоянное прослушивание, собственная синхронизация между устройствами, обязательный Obsidian, автоматическая отправка дневника в облако, обещание превосходства над Freeflow без сопоставимых измерений.

## Decisions

1. Сохранить Python/PyObjC и существующие движки. Переписывание на Swift не решает подтверждённые проблемы само по себе и увеличивает объём миграции. Новое окно дневника использует общий сервис с меню и настройками.
2. Контроллер сессии владеет состояниями idle/starting/recording/processing/delivering/error. Listener только ставит события в очередь; UI работает на главном потоке, I/O и inference вне него. UUID, время начала с часовым поясом, режим, целевое приложение и неизменяемый снимок настроек фиксируются один раз. Длительности измеряются monotonic/perf_counter. Явно обрабатывать отмену, раннее отпускание до открытия микрофона и смену настроек в процессе.
3. Отдельный маршрут journal сохраняет без Cmd+V. Старые клавиши и tap/hold остаются по умолчанию. Мастер настройки обнаруживает одинаковые назначения и даёт тест записи. В процессе обработки повторное нажатие даёт видимый ответ, а не запускает конкурирующую сессию.
4. Markdown остаётся источником сохранённых заметок. SQLite хранит восстанавливаемый поисковый индекс и отдельную постоянную очередь доставки: UUID, текст, дата, destination snapshot, status, attempts, next_retry, error. Индекс можно перестроить; очередь нельзя удалять при очистке статистики. После commit очереди показывать «В очереди», после fsync файла «Сохранено». После успеха удалять текст из очереди, оставляя минимальную квитанцию. Аудио по умолчанию на диск не писать; при аварии до фиксации текста полное восстановление не гарантируется.
5. Очередь повторяет запись с ограниченной экспоненциальной задержкой и кнопкой повторить, сохраняется после перезапуска. Недоступная старая папка не заменяется новой молча. Повтор использует тот же UUID. Для частичной записи нужны begin/end-маркеры, контроль завершённого блока и протокол восстановления с копией повреждённого файла; наличие одного старого маркера не является достаточным подтверждением доставки. Старый формат читается совместимо.
6. Внешние правки: перед редактированием хранить хеш версии; при изменении перечитать файл и показать конфликт, не затирать. Для собственных правок использовать временный файл, fsync и атомарную замену; сохранять ограниченные резервные копии. У произвольного внешнего редактора нет общего lock-протокола: полностью исключить гонку невозможно. При обнаруженной замене файла повторно сверять запись по UUID, сохранять конфликтную копию и показывать восстановление. Не заявлять абсолютную транзакционность общей папки.
7. Файл дня выбирается по локальной дате начала сессии, зафиксированной вместе с timezone. Плоский YYYY-MM-DD.md остаётся совместимым default; YYYY/MM/YYYY-MM-DD.md опционален только для новых записей. Заголовок и шаблон добавляются только в новый файл. Не переносить существующие файлы автоматически. Запретить выход за выбранную папку и переход через symlink, задать ограничения размера и обработку невалидного UTF-8.
8. Записи имеют тип note/task/idea; задача представляется `- [ ]`. Голосовые команды распознаются только при явном включении и строгом префиксе, обычные фразы не превращаются в команды. Поиск локальный, индекс обновляется при открытии/изменении файла; при ошибке индекса возможен просмотр MD. Первая версия использует редактор текста с предпросмотром, без сложного rich-text round-trip.
9. Скорость: сначала измерить открытие устройства, первый аудиоблок, overlay, хвост, ASR, cleanup, очередь, fsync и попытку вставки. Прогревать модель без открытия микрофона. Не сокращать хвост и не менять фильтры тишины без проверки начала/конца фразы. Для cloud обязательны timeout, отмена и видимый fallback; raw-текст доступен при ошибке cleanup. Успешный Cmd+V не считать доказательством доставки в чужое приложение.
10. Live-preview и AI-итоги внедрять после основной приёмки. Предварительный текст отображать в UI, в итоговый MD писать завершённый блок один раз. Итоги создаются по кнопке, сохраняются отдельным разделом после просмотра; исходные записи сохраняются. Облачный вариант явно показывает, что текст дня будет отправлен выбранному провайдеру.

## Проверка и целевые показатели

Это проектные цели, не уже достигнутые результаты. Этап 1 фиксирует модель, CPU, macOS, устройство, питание, версии, сеть и длительность аудио. Если цель недостижима, документировать измерение и отдельное решение, не объявлять PASS.

| Показатель | Приёмка |
|---|---|
| Срабатывание | 0 пропусков и двойных запусков в 500 воспроизводимых циклах tap/hold; отдельно физические клавиши, смена раскладки и sleep/wake |
| Реакция | p95 до видимого подтверждения <=100 мс; до первого аудиоблока <=250 мс на встроенном микрофоне; Bluetooth измеряется отдельно |
| Готовый текст | Для тёплых сессий с аудио 5-15 с уменьшить p95 от отпускания до доступного результата минимум на 20% относительно baseline, отдельно local/cloud, без ухудшения качества |
| Холодный запуск | Отдельный p50/p95; отсутствие зависания интерфейса, видимое состояние загрузки; не смешивать с тёплым показателем |
| Качество | Корпус минимум 120 размеченных записей RU/EN/смешанных, включая шум, имена, числа и отрицания; WER не хуже baseline более чем на 1 процентный пункт в каждой группе; 0 новых смысловых ошибок в фиксированном наборе чисел/отрицаний |
| Доставка | 1000 записей с повтором, отказом диска/прав, перезапусками и обрывом записи; каждый подтверждённый UUID восстановлен ровно один раз, конфликты явно показаны |
| Дневник | p95 открытия дня <=300 мс и поиска <=500 мс на фиксированном корпусе 10000 записей после индексации; холодная индексация с прогрессом и отменой |

На каждую конфигурацию задержек минимум 100 повторов; сырые измерения без текста диктовок, p50/p95 и число ошибок в отчёте. Ручная приёмка: разрешения macOS, встроенный/USB/Bluetooth микрофон, отключение устройства, сон, RU/EN раскладка, TextEdit/браузер/редактор, смена фокуса, малая ширина окна, клавиатурная навигация и VoiceOver. Тестовый корпус синтетический или явно предоставленный; личные заметки не использовать.

## Risks / Trade-offs

- Конкурентное сохранение внешним редактором -> проверка версии, резервная копия, обнаружение конфликта; ограничение описано выше.
- Сеть/модель меняют задержку -> фиксированные условия и отдельные отчёты, равный приоритет local/cloud.
- Дополнительная запись на диск увеличивает latency -> замерять queue commit и fsync отдельно, не показывать преждевременный успех.
- Постоянная очередь содержит текст -> права 0600, отсутствие текста в логах, явная очистка очереди отдельно от истории, private mode запрещает сетевую отправку.
- Новый индекс или повреждённая БД -> резервная копия, восстановление индекса из MD; повреждённую очередь сохранять для восстановления, не пересоздавать с потерей данных.

## Migration Plan

Этапы: baseline -> контроллер и клавиши -> постоянная доставка -> UI дневника -> измеренная оптимизация -> дополнительные функции -> приёмка сборки. Каждый этап включается независимо и сохраняет обычную диктовку.

Старые настройки экспорта и отдельные файлы сохраняются. Перед миграцией конфигурации/БД сделать копию и добавить номер схемы. Новая версия читает старые MD без массовой перезаписи. Откат сначала выключает journal/live/summary, затем возвращает предыдущую сборку; очередь не удаляется, pending экспортируется новой утилитой восстановления до отката при несовместимости схемы.

OpenSpec является источником плана этого изменения; существующие Spec Kit документы не удаляются и не переписываются как будто уже реализованные функции отсутствовали.
